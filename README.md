# KT 정산 자동화 시스템

KT 정산 raw 데이터와 통합플랫폼 데이터를 대사(reconciliation)하여  
인보이스·매출현황·어음확인·자금예측 보고서를 자동으로 생성하는 Python 스크립트입니다.

---

## 파일 구성

| 파일 | 설명 |
|------|------|
| `run_settlement.py` | 메인 정산 자동화 스크립트 |
| `run_reconcile.py` | 대사 결과 검증 스크립트 |
| `make_sample_data.py` | 테스트용 샘플 데이터 생성 |

---

## 사용 방법

### 1. 필수 파일 준비

같은 폴더에 아래 두 파일을 넣어주세요:

- `kt_raw.xlsx` — KT 정산 원본 (정답 기준)
- `platform.xlsx` — 통합플랫폼 정산 데이터

### 2. 실행

```bash
python run_settlement.py
```

첫 실행 시 컬럼 구조를 출력하고 매핑을 확인한 뒤 진행합니다.

### 3. 출력 파일

| 파일 | 내용 |
|------|------|
| `정산결과_YYYYMMDD.xlsx` | 인보이스 / 매출현황 / 어음확인 / 자금예측 (4개 시트) |
| `대사검토_YYYYMMDD.xlsx` | 플랫폼누락 / 반품결과 / 금액불일치 / 요약 (5개 시트) |
| `settlement_log.txt` | 실행 로그 |

---

## 정산 주기 자동 판단

| 실행일 | 대상 기간 |
|--------|-----------|
| 매월 16일 | 당월 1일 ~ 15일 입고분 |
| 매월 1일 | 전월 16일 ~ 말일 입고분 |
| 그 외 | 실행 시 직접 입력 |

---

## 대사 로직 요약

```
[STEP 1] 입고일 기준 기간 필터링
[STEP 2] KT 파일에서 반품 주문 선분리 (주문유형 자동 탐지)
[STEP 3] 일반 주문 대사 — 주문번호 기준
         A. 양쪽 일치    → 정상 (금액 ±1원 이내)
         B. KT에만 존재  → 플랫폼 누락 (빨간 하이라이트)
         C. 플랫폼에만   → KT 미포함 별도 기록
[STEP 4] 반품 대사 — 요청번호 기준 매칭
```

## 샘플 데이터로 테스트

```bash
python make_sample_data.py   # kt_raw.xlsx / platform.xlsx 생성
python run_reconcile.py      # 대사 결과 검증 (누락 3건, 반품 2건 확인)
```

## 매핑 테이블 설정

`run_settlement.py` 상단의 딕셔너리를 실제 값으로 교체하세요:

```python
# 서비스카테고리 → 관리회계 / 담당자
SVCCAT_MAP = { "IT서비스": ("IT관리회계", "홍길동"), ... }

# 담당자 → 일반/통신 구분
PERSON_TYPE_MAP = { "홍길동": "일반", ... }

# 협력사 규모 (어음 발행 판단)
COMPANY_SIZE_MAP = { "삼성전자": "대기업", ... }
```

`existing_report.xlsx`를 같은 폴더에 넣으면 매핑 시트를 자동으로 읽어옵니다.
